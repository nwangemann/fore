# Review and status, 2026-11-26

A review of the app, the docs and the development process after the roadmap's agent steps (sections 1–8) were finished. The changes from this pass are listed at the end and landed in one commit.

## Status

- **Roadmap:** 17 of 18 steps done. The one left, [9.1 manual checks](../backlog/manual.md), needs a person.
- **Build:** `main` is clean and in sync with GitHub. `check` and `e2e` pass on every recent push.
- **Size:** about 3,200 lines of app TypeScript (excluding vendored icons), 430 lines of unit and service tests, one end-to-end test, 11 ADRs, 25 commits before this review.
- **Verified vs not:** see the backlog's [State](../backlog/README.md#state). In short, everything a browser and CI can show has been checked. Location with a real prompt, VoiceOver, a real phone and native builds have not.

## The application

Strengths:

- **Clear layering.** `src/core` is pure TypeScript with no React or Expo imports. `src/services` only fetches and parses, and `useDashboard` composes four TanStack Query queries. The boundaries hold everywhere: no exceptions were found.
- **Real decisions, recorded.** Seasonal par, place-local time, cache-first loading and the weather-driven theme each solve a problem that was observed, and each has an ADR.
- **Failure handling.** Every card has a loading, empty and error state, and a failed refresh keeps the last good data.
- **Accessibility beyond the basics.** Each grid cell is one spoken sentence, there is a keyboard focus ring, and contrast is measured and recorded per palette.
- **Tests where they pay.** Unit tests cover scoring, outlook, parsing and speech. Service tests use recorded API responses, and one offline Playwright test runs the real web build.
- **Code hygiene.** Strict TypeScript, lint and format are clean. There are no TODOs, no `any` and no suppressed lint rules.

Gaps and risks:

- **No live demo.** A reviewer has to clone and run the project to try it, which is the biggest barrier for a portfolio piece. `npx expo export -p web` already produces a static site that could be hosted on GitHub Pages or any static host.
- **No release marker.** The version is `0.1.0` and there are no tags. A `v1.0.0` tag at the end of the roadmap would mark a finished state.
- **Repository metadata.** The GitHub description still uses the old wording, and the repo has no topics or homepage link.
- **Native is unproven.** The README says that iOS and Android are untested, which is accurate. `npm run ios` and `npm run android` stay as entry points only.
- **Single-locale copy.** The text is English only, and units are limited to imperial and metric. This is acceptable for the scope.
- **Small unused exports.** A few types and constants are exported but only used in their own module. This is harmless and was left alone.

## Process

The work followed a repeatable loop. A v0.1 build came first, then a dated self-review, then a roadmap of session-sized steps. Each step ran in a fresh agent session against written instructions and ended in a checked, committed, pushed state ([ai-workflow.md](../ai-workflow.md)).

What worked:

- **One step per session.** Each step had its own file list and a "Prove:" line. Scope stayed small and reviewable, and no step had to be redone.
- **Written state over chat history.** The backlog's State section, the ADRs and the `fore-dev` skill let each session start cold.
- **Hard gates.** A pre-commit `npm run check` and two CI jobs on every push meant `main` was never red at the end of a step.
- **Honest verification.** Every step separated what was verified from what was not. Person-only checks were collected at the end instead of blocking work.

What cost time or needed attention:

- **Personal details in history.** The first commit carried a machine hostname as its author. It was found and rewritten before the first push, and an earlier check would have avoided the rewrite.
- **Environment drift.** Node sat outside the shell PATH, which broke the portable preview config once. `scripts/web-preview.sh` now finds Node.
- **Sequencing on one branch.** Steps share `main`, so a step that rewrote history had to finish before the next could start. Running steps strictly in order avoided conflicts.

## Recommendations

In order of value for a portfolio reader:

1. **Host a live demo.** Add a GitHub Pages deploy of the web export, and link it from the README and the repo's homepage field. This needs a decision on hosting.
2. **Update the GitHub repo metadata.** Set the description to match `package.json`, and add topics such as `expo`, `react-native-web`, `tanstack-query`, `weather` and `typescript`.
3. **Tag `v1.0.0`.** Set the version in `package.json` and `app.json` and tag the release once the manual checks pass.
4. **Run the manual checks (9.1).** These are location, a phone, VoiceOver and a cold read of the README.
